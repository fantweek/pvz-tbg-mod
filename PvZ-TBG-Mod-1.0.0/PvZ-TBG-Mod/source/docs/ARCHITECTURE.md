# Устройство PvZ TBG Mod

```
src/
  mod.cpp        ядро: инициализация, хуки, tick() на игровом потоке, все игровые правки
  ui.cpp         меню Dear ImGui (DX11) в отдельном окне и потоке
  cfg.h          Cfg (все настройки), CFG_FIELDS, ini, cfgSanitize, готовые сборки (kBuilds)
  shared.h       состояние, общее для потоков: Shared S, команды Cmd, прохождения RunState
  launcher.cpp   PvZModLauncher.exe: запуск игры, внедрение DLL, режим --watch (трей), автозапуск
  plat.h         <windows.h> или подмена winshim.h для тестов (PVZ_TEST)
  version.h      версия проекта (единственное место)
tests/           test_logic.cpp + winshim.h: логика мода на подделанной памяти игры (Linux, 32-бит)
third_party/     Dear ImGui (только нужные файлы)
scripts/         build.py (сборка/тесты/архив), make_assets.py (иконка и баннер)
tools/screenshots/  снимки меню для README: настоящий drawUi() + программный растеризатор на Linux (PVZ_SHOT)
```

## Как это работает

1. **Внедрение.** `PvZModLauncher.exe` запускает игру (через `steam://rungameid/3590`, если игра в `steamapps`) или находит запущенную, находит окно класса
   `MainWindow` с заголовком «Plants…» и делает `CreateRemoteThread(LoadLibraryW)` с путём к `pvzmod.dll`. Режим `--watch` делает это сам при каждом запуске игры.
2. **Проверка версии.** Поток инициализации DLL ждёт окно игры (`findOwnGameWindow`: окна именно этого процесса), проверяет базу `0x400000` и метку времени PE
   (`G::TIMESTAMP`). Не совпало — мод ничего не трогает.
3. **Игровой поток.** В таблице импорта exe подменяются `Sleep` и `PeekMessageA/W`; на каждый вызов (не чаще раза в миллисекунду) выполняется `tick()` — так
   правки памяти идут из потока игры без гонок с ней.
4. **Меню.** Отдельный поток с окном и ImGui. Клавиша Tab опрашивается через `GetAsyncKeyState`. Настройки передаются в игровой поток копией `Cfg` под
   критической секцией (`S.cfg`), одноразовые действия — через `S.cmd[]` (`InterlockedExchange`).
5. **Патчи кода** (`Hack`, `hackSet`): байты по адресу сравниваются с ожидаемыми «до» и «после»; чужая версия — патч отключается.

## Память игры

Все смещения — в `namespace G` в начале `mod.cpp` (LawnApp, Board, Plant, Zombie, SeedBank/SeedPacket, профиль игрока). Доступ — `at<T>(ptr, off)`; перед чтением
структур проверяется `okp(ptr, size)` (страница читаема).

Приёмы:
- **Дельта-масштабирование** (ценность солнца и монет): мод масштабирует положительные приращения, которые игра добавила сама; дробь копится в аккумуляторе.
- **Новые сущности** (растения, зомби) находятся сравнением «живой / был живым» в массивах `prevP` / `prevZ`; состояние сбрасывается при новом уровне (`Lvl`).
- **Заморозка сборки:** пока `runs[i]` активна для текущего игрока, `tick()` берёт `buildCfg(i)` вместо пользовательских настроек и блокирует все команды.

## Как добавить настройку

1. Поле в `Cfg` (`cfg.h`) и имя в `CFG_FIELDS`; ограничение значения — в `cfgSanitize` (NaN уходит в нижнюю границу).
2. Логика в `tick()` (`mod.cpp`) — через `c.<поле>`; состояние уровня — в `Lvl`.
3. Элемент меню в нужной `tab*()` (`ui.cpp`): `Card(...)` + `EndCard()` всегда парой; ID виджетов в карточке должны различаться.
4. Тест в `tests/test_logic.cpp`: `World w; Cfg c; c.<поле> = ...; setCfg(c); w.step(n); CHECK(...)`.
5. Строка в `CHANGELOG.md` и `docs/FEATURES.ru.md`.
